## 동일 조건 성능 비교

Chrome 1440×1000, CPU 4배 제한, RTT 150ms, 다운로드 200,000B/s, API 응답 지연 250ms, 외부 스크립트 지연 600ms, 6초 관찰. 새 브라우저 컨텍스트에서 전후 순서로 5회 교차 측정했다. 이 비교는 **기존 운영 버전 4ded462 대비 이번 화면 개선**이며 최초 속도 개선의 비교와 별개다. 외부 이미지 변동을 제거하기 위해 동일 SVG fixture(로고는 원본)를 사용했다. 실제 운영 속도나 사진 LCP를 보장하는 측정은 아니다.

| 지표 | 이전 중앙값 | 개선본 중앙값 | 차이 |
|---|---:|---:|---:|
| FCP | 2,172ms | 2,228ms | +56ms (+2.6%) |
| LCP (통제 이미지 조건) | 2,172ms | 2,228ms | +56ms |
| 로고 DOM 표시 감지 | 2,127.8ms | 2,186ms | +58.2ms |
| Long task 누적 | 917ms | 971ms | +54ms |
| 초기 JS+CSS 압축 전송량 | 196,898B | 199,720B | +2,822B (+1.43%) |

FCP 범위는 이전 2,156–2,316ms, 개선본 2,200–2,260ms이다. 이번 UI 확장에는 작은 비용이 관찰됐으며 성능 향상이라고 주장하지 않는다. 로고 별도 이미지 요청은 양쪽 모두 0회, hero2 요청은 양쪽 모두 1회로 기존 개선을 유지했다. 로고 설정 읽기 1회도 유지되지만 로고 초기 표시를 기다리는 구조가 아니다. 지역 조회는 메뉴를 열기 전 0회이며 추가 초기 API 병목은 없다. CSS/컴포넌트 추가와 캐러셀 대신 전체 상품을 그리는 변경이 있고, 이 수치만으로 각 비용을 분리해 단정할 수는 없다. 브라우저 오류는 전후 10회 모두 0건이다.
